# TOP Handoffs Protocol v1.0

Version: 1.0
Status: Draft
Author: ChatGPT & Paul
Applies To: TOP Engineering System (TES)

---

# Purpose

TOP-Handoffs is the communication protocol for the TOP Engineering System.

Its purpose is to eliminate manual conversation transfer between AI agents by replacing conversation with standardized engineering artifacts.

The primary communication object is no longer chat history.

The primary communication object is the Handoff Package.

---

# Design Principles

## 1. Artifact Driven

AI agents exchange artifacts.

They do not exchange conversations.

Every engineering activity produces structured artifacts that become the input of the next engineering activity.

---

## 2. Single Source of Truth

Every task owns exactly one Handoff Package.

No information should exist only inside a chat conversation.

Anything required by another AI agent must exist inside the Handoff Package.

---

## 3. Executive Summary First

Human attention is limited.

AI context is limited.

Every Handoff Package must contain an Executive Summary that allows another AI or a human to understand the current state within one minute.

Detailed reports remain available but are secondary.

---

## 4. Separation of Responsibility

Each AI agent owns different responsibilities.

ChatGPT

- Architecture
- Product decisions
- Sprint definition
- Acceptance criteria
- Final decision

Codex

- Implementation
- Refactoring
- Code generation
- Technical report

Qoder

- Local review
- Architecture verification
- Regression review
- Merge recommendation

GitHub

- Source of Truth
- Version history
- Pull Request workflow

TOP-Handoffs

- Communication protocol
- Engineering artifacts
- Cross-AI handoff

# Standard Handoff Package

Every TASK directory contains the following files.

## 01-TASK.md

Created by ChatGPT.

Defines:

- Objective
- Scope
- Constraints
- Acceptance Criteria
- Execution Mode
- Expected Deliverables

This document is the implementation contract.

---

## 02-EXECUTIVE-SUMMARY.md

Created by Codex.

Maximum length:

One screen.

Contains:

- Status
- Files Changed
- Database Changes
- API Changes
- Service Changes
- Tests
- Recommendation
- Blocking Issues
- Decision Required
- Next Action

This is the default document read by ChatGPT.

---

## 03-PATCH.diff

Generated by Codex.

Contains the exact code difference.

Never manually edited.

---

## 04-FULL-REPORT.md

Generated by Codex.

Contains:

- Design decisions
- Technical explanation
- Migration notes
- Risks
- Complete implementation report

Length is unrestricted.

---

## 05-LOCAL-REVIEW.md

Generated by Qoder.

Contains:

- Architecture Review
- Domain Review
- Compatibility Review
- Test Results
- Blocking Issues
- Merge Recommendation

---

## STATUS.md

# Communication Rules

Rule 1

ChatGPT never needs the complete Codex conversation.

Rule 2

Codex reports through artifacts.

Rule 3

ChatGPT reads Executive Summary first.

Only when necessary does ChatGPT open Full Report.

Rule 4

Human operators should avoid manually copying long conversations.

Instead, they should direct AI agents to the corresponding Handoff Package.

Example:

"Read TOP-Handoffs/TASK-TOP-007."

instead of

"Here are 400 lines copied from Codex."

Rule 5

The Handoff Package becomes the permanent engineering record.

Chat conversations are temporary.

Artifacts are permanent.
