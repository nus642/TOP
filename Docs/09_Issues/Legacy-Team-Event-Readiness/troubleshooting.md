# 开赛失败排查表

> 裁判报告"无法开赛"时，按此表逐项排查。优先级从上到下。

---

## 症状 1：裁判点击"开始 setup"后弹窗阻断

### 1A. "选手【XXX】不在系统名单中"

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 确认选手姓名拼写 | 对比任务中的姓名与 players 表 | 完全一致（无空格/全角差异） |
| 2. 检查 players 表 | master → 名单管理 → 搜索该姓名 | 应存在 |
| 3. 如果不存在 | 在 players.html 手动添加该选手 | 添加后重试 |
| 4. 如果存在但不匹配 | 检查是否有全角空格、前后空格、大小写差异 | 修正姓名 |

**根因分析：**
- CSV 导入时列头不匹配 → 整列被跳过 → 选手未入库
- 领队排阵时手输姓名与 CSV 不一致
- CSV 中用分隔符拆分的名字与排阵不匹配

### 1B. "选手【XXX】未完成免责签到"

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 确认签到状态 | players.html → 查看该选手 checked_in 列 | 应为 true |
| 2. 如果未签到 | 方式 A：让选手扫码签到 | 签到后重试 |
| 3. 如果未签到 | 方式 B：裁判长在 players.html 手动切换该选手签到 | 切换后重试 |
| 4. 如果大面积未签到 | 确认主办方已线下核验全部人员到场后，使用"一键全签到" | 全部签到后重试 |

> **⚠️ "一键全签到"使用前提：主办方已线下核验全部人员实际到场。**
> 不可为绕过系统校验而对未到场人员使用，否则存在免责签署缺失的法律风险。

## 症状 2：裁判看不到任务

### 2A. 裁判登录后任务列表为空

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 确认下发已执行 | master 面板查看是否点击过"扫描核碰" | 应有下发记录 |
| 2. 确认房间状态 | master 面板查看 team_event 房间 | status 应为 completed |
| 3. 确认排阵已提交 | master 面板查看 team_lineups | 双方都应有记录 |
| 4. 如果未下发 | 回到 Phase 5 执行核碰下发 | 下发后重试 |
| 5. 如果排阵未完成 | 通知领队完成排阵 | 排阵后重新下发 |

> **注意：未排阵的房间只能等待领队完成排阵或取消该房间，禁止强行下发空白对阵。**

### 2B. 裁判提取任务时报错

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 检查网络 | 裁判手机能否访问 data.php | 应能访问 |
| 2. 检查赛事码 | 裁判输入的赛事码是否正确 | 与创建时一致 |
| 3. 检查服务器 | data.php 是否返回正常 JSON | 浏览器直接访问测试 |

## 症状 3：日程建房失败

### 3A. 解析结果为空

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 检查 VS 格式 | Excel 中 VS 单元格是否含大写 "VS" | 必须是大写 VS |
| 2. 检查 VS 位置 | VS 上下行是否有队名 | 上=左队，下=右队 |
| 3. 检查淘汰赛过滤 | 单元格是否含"半决赛/决赛/胜方/负方" | 含则被过滤 |
| 4. 检查文件格式 | 是否为 .xlsx 或 .xls | 不支持 CSV 日程表 |

### 3B. 解析出的队名与大名单不一致

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 对比队名 | 日程表队名 vs CSV 队名 | 应完全一致 |
| 2. 在预览页编辑 | team_import 预览页可直接修改队名 | 修改后与大名单一致 |
| 3. 重新导入 | 如果差异大，修正 Excel 后重新导入 | 一次性匹配 |

---

## 症状 4：领队无法排阵

### 4A. 查询不到对阵信息

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 检查赛事码 | 领队输入的赛事码 | 与创建时一致 |
| 2. 检查房间号 | 领队输入的房间号（如 T01） | 与建房时一致 |
| 3. 确认房间已创建 | master 面板查看 team_event | 应有该房间 |

### 4B. 名单为空（看不到己方球员）

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 确认大名单已导入 | master → 名单管理 | 有该队球员 |
| 2. 确认队名匹配 | 排阵页面显示的队名 = players 表中的队名 | 完全一致 |
| 3. 如果未导入 | 先完成 Phase 1 | 导入后刷新 |

---

## 症状 5：比分提交失败

| 排查步骤 | 操作 | 预期结果 |
|----------|------|----------|
| 1. 检查网络 | 裁判手机能否访问 data.php | 应能访问 |
| 2. 检查 localStorage | 裁判是否清除了浏览器数据 | 不应清除 |
| 3. 如果数据丢失 | 裁判长在 master 手动录分 | 作为兜底方案 |

---

## 快速应急速查

| 紧急情况 | 解决方案 | 限制条件 |
|----------|----------|----------|
| 个别选手未签到 | players.html → 手动切换该选手 | 必须确认本人到场 |
| 大面积选手未签到 | players.html → 一键全签到 | **仅限主办方已线下核验全部人员到场后** |
| 领队未排阵 | 通知领队完成排阵 | 未排阵房间不可下发，**禁止强行下发空白对阵** |
| 选手姓名不匹配 | 手动在 players.html 编辑姓名 | 确保与排阵选择完全一致 |
| 裁判看不到任务 | 重新执行核碰下发 | 确认双方排阵已提交 |
| 比分提交失败 | 裁判长手动录分 | 作为兜底方案 |
| 浏览器缓存旧页面 | Ctrl+F5 强制刷新 | 无 |
| 整个系统不可用 | 检查 Docker/PHP/MySQL 服务 | 无 |
